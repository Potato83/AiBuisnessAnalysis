# День 2 — локальный результат

## Реализовано

- Python-функция `generate_insights(company_profile, news, bank_sources)`.
- Объяснимое ранжирование восьми синтетических новостей для двух компаний.
- Признаки: ОКВЭД, регион регистрации/операций, кредитные и депозитные продукты,
  сумма кредитного долга относительно выручки, ВЭД, контрагенты и прямое упоминание.
- Поля insight по `docs/API_CONTRACT.md` и дополнительный trace.
- HTTP-адаптер `deepseek/deepseek-v4.1-flash` через API Mira.
- Автоматическая загрузка `backend/agent/.env`; модель и параметры заданы,
  ключ добавлен пользователем. Файл игнорируется Git.
- Явный mock и включаемый параметром fallback; неподтверждённый `bank_view=null`.
- Изолированные тесты без сети и без настоящего ключа.

Два полных результата демо: `data/synthetic/agent_day2_mock_results.json`.
Оба результата получены в режиме **mock**, каждый содержит восемь ранжированных
новостей. Это тестирование локальной логики и контракта, не качества LLM.

Локальная проверка: **47 unit-тестов прошли** (`python -m unittest discover -s tests -v`).
Восемь результатов каждой компании прошли валидацию `InsightResult`; все 16
значений `bank_view` равны null. Тесты HTTP-адаптера используют подменённые ответы.

| Одна новость: demo-news-rate | Заёмщик | Компания с депозитами |
|---|---|---|
| Балл релевантности | 50 | 25 |
| Категория | high | medium |
| Канал влияния | Стоимость финансирования, условия действующих кредитов неизвестны | Доходность депозитов и сроки размещения |
| Позиция банка | null | null |

## Проверка реальной LLM

После перехода на DeepSeek через API Mira два реальных вызова выполнены успешно
**без** `--fallback-mock`: восемь новостей для каждой из двух компаний,
16 валидных инсайтов. Проверены модель ответа, JSON, ссылки, порядок ранжирования,
различия интерпретаций общей новости и `bank_view=null`. Общая длительность — 82.94 с.
Два результата: `data/synthetic/agent_day2_llm_results.json`.
